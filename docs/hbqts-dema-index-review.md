# QTS Figure A.7: DEMA 16/8 index research contract

This review covers only `hbqts_dema16_8`. Howard B. Bandy's *Quantitative Trading Systems* (2007), Figure A.7 on printed pages 322–323, contains a complete demonstration trading rule within a custom objective-function example. Printed page 324 illustrates the S&P 500 cash index for 1995–2005. The review does not reproduce that optimization, custom ranking, source data, book equity curve or native AmiBroker results.

The companion `Figure_A_7.afl` defines ordered DEMA periods 16 and 8 and a one-bar holding-clock default. Raw Buy is `Cross(DEMA(C,16), DEMA(C,8))`. Raw Sell is the reverse cross or `BarsSince(raw Buy) >= 1`. Sell then passes through `ExRem(Sell, Buy)`; Buy remains raw. The raw clock and ExRem state use all supplied genuine observations before a selected window. They are not restarted by a selected date, a filled entry or portfolio state. Before the first raw Buy, the clock branch is inactive; a genuine reverse cross can still set Sell. The demonstrated custom backtester reads completed statistics to create an objective metric; it supplies no independent execution or sizing rule.

Only actual SPX cash-index prices and a separately declared actual NIFTY 50 cash-index adaptation are in scope. An ETF, constituent stock, other index, derivative or basket cannot substitute. NIFTY history begins at the existing qualified 2000 cutoff before indicator initialization; earlier excluded rows are not reused as hidden warmup. Daily observations are the selected research application of the current-array AFL formula.

Both internal smoothing states start from the first actual close. This follows the dated 2003 developer loop in the official DEMA documentation, which explicitly differs from standalone EMA initialization. The selected binary64 recurrence is `e1 += alpha*(close-e1)`, `e2 += alpha*(e1-e2)`, then `e1+(e1-e2)`, with `alpha=2/(period+1)`. Both DEMA arrays are valid at index zero; the first cross requires two observed states. No 16/32-bar maturity or fabricated earlier value is inserted. Arithmetic order is declared and native bit parity is not claimed. Exact equality does not cross.

The book code omits trade delays, fill-price assignments, sizing, commission and initial capital. The declared research execution uses finalized daily close signals and idealized same-close zero-delay fills, one long normalized unit-exposure position, no pyramiding and a flat selected start. Earlier signal arrays retain their state, but an earlier position is not inherited. A true entry on the selected last close stays open and is marked there. A genuine one-session selected window is valid with its supplied earlier prefix. These conventions do not establish executable cash-index trading or funded capital.

The initial reporting convention retains the application's existing binary64 normalized-return model: each trade returns `exit/entry - 1 - 2*side_rate`, with user fees and slippage in bps per side of entry allocation. Intermediate held marks deduct one cost side. Closed exits and terminal open marks deduct two sides; the open second side is an estimated liquidation cost, not a filled exit fee. Gross independently compounds the same fills at zero cost. Ledger contributions use net pretrade normalized allocation, not cash quantities or contract money. Rollover, capital sizing, taxes, financing and verified derivative execution are unavailable.

Closed-trade statistics exclude open marks. Zero-return closed trades are non-wins for win rate and loss-streak reporting. Exposure counts observed entry-through-exit sessions inclusively; drawdown duration counts observed sessions, while tradesheet Days Held is the calendar date difference.

An exact canonical-decimal economic-sign diagnostic is frozen separately from the initial binary64 model. It uses shortest round-trip decimal representations of loaded Rust prices and the two cost components, not undisclosed original vendor decimal strings. The exact numerator `(exit-entry) - 2*entry*(fees_bps+slippage_bps)/10000` determines economic sign. A proven exact-zero trade must not be published as a winner. This candidate remains held for reporting until the independently observed binary64 discrepancy receives a coherent reviewed treatment across returns, curves, ledger and statistics. Neither the shared `Trade::ret` helper nor unrelated methods are silently changed.

Only the literal defaults 16/8/1 are reviewed; changed, unknown, malformed and nonsingleton parameter grids are rejected before float rounding can turn them into defaults. Full relevant source history must have positive finite valid OHLC, strictly increasing valid dates and one instrument. Invalid observations are held, not dropped, filled or reseeded. Future observations beyond the selected endpoint do not affect that admission or the computed arrays.
