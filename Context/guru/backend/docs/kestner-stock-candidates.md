# Kestner stock research contract

The bounded batch contains **three methods from one book by one author**: Lars Kestner, *Quantitative Trading Strategies* (2003). Channel40/20 is on printed pp.139–140, simple SMA10/40 on p.145, and momentum80 on p.150. Printed p.139 specifies completed-close decisions and next-session opening execution. Original dollar-volatility sizing (pp.135,137) and original mixed-instrument study figures remain separate from normalized selected-stock percentage research.

The engine admission covers only the exact book `lkqts` and IDs `lkqts_cb4020`, `lkqts_ma1040`, `lkqts_mom80`, on server-qualified actual individual stocks. Index, ETF, derivative, unqualified ticker and basket requests cannot inherit that admission. Other Kestner methods remain held. Engine admission, live deployment and measured availability are separate gates: this code does not itself update homepage counts or the Downloads workbook.

## Source rules and declared conventions

- Channels include the current close:40 genuine closes first exist at zero-based index39. Inclusive extrema allow ties with a previous high/low. The prose does not publish indexed code or tie operators; this is a declared interpretation.
- If both40-close directions are simultaneously true, a flat account stays flat. An existing20-close exit is honored. An unambiguous opposite40-close entry closes and reverses at the same next actual open. A20-close exit wins over a same-side entry; same-side re-entry requires a later signal. These collision priorities are declared research conventions, not uniquely established source instructions.
- SMA10/40 needs an observed cross using two valid average comparisons: first possible signal index40. Previous difference≤0/current>0 signals long; previous≥0/current<0 signals short. Current equality alone neither exits nor enters. No position is created from the first average relationship alone. The implementation retains the ordinary engine's binary64 rolling averages; source prose does not specify machine arithmetic. The independent reference uses direct rational window sums and does not imitate those rolling operations or introduce an epsilon.
- Momentum compares `C[i]` with `C[i−80]`, requiring81 observations and first signal index80. Strict greater/less signals long/short. Equality retains an existing holding and creates no order while flat.
- The selected window starts flat; genuine supplied earlier history supplies indicators. No predecessor prices or positions are fabricated. A last-close signal without a following supplied session cannot fill. An actual final-open entry may remain an open holding at the final close.
- Source defaults are fixed. Unknown, changed, nonfinite, malformed or decimal values that merely round to a default fail before results. Optimizer schemas and raw grids permit only singleton default settings. No fitting to book performance figures is performed.

## Accounting and causal API output

The ordinary normalized percentage account is retained. A same-open reversal finishes the old position, pays its exit side, allocates the resulting normalized equity to the new position, pays the new entry side and marks at that session's close. Per-side fees/slippage are return deductions on the deployed normalized allocation; observed fill prices are not rewritten. No capital, tax, borrowing, margin, financing, lot or original dollar-volatility model is invented. Unsupported nonpositive/nonfinite accounts remain unavailable without resets or clipping.

Terminal marking is not a closed trade. The ordinary account deducts a separately disclosed estimated liquidation side on the final open mark. Closed counts, arithmetic net-return sums and average closed-trade returns exclude that holding; marked equity remains a separate model.

Each detail trade has an `execution_clock` containing separate entry-signal, entry-fill, exit-signal, exit-fill and terminal-mark fields. Signals include causal rule-state values from the completed signal close. Fill events use actual next-session opens. An open holding has null exit-signal/exit-fill fields and an explicitly unfilled terminal mark. The legacy `signal` field retains its exit-rule/terminal-observation meaning. Kestner `at_entry` uses the prior completed signal session; terminal `at_exit` is null. SMA diagnostic arrays are computed once per report and reused.

## Validation evidence and its limits

The source-event fixtures were hand frozen by a reviewer before reading Rust or references:15 executable event cases plus a diagnostic exposing unspecified channel priorities. Separate tests cover our declared collision convention. The13 synthetic account schedules at four cost modes include eight expected nonpositive-account holds. The account oracle was frozen before Rust capture, but its author disclosed prior exposure to legacy accounting; this is not blind independent account verification.

The broader data-independent Rust suite passes790 tests, with five opt-in tests ignored and one legacy whole-catalogue equity test excluded. Its initial invocation failed before calculation because its private default `idx_data.csv` path was absent. That exception is not reported as a passing full-corpus backtest.

Four independently bound actual-stock histories were checked: AAPL/MSFT (1990–2001) and RELIANCE/HDFCBANK (2001–2010), with all genuine prefixes retained. Three methods at zero costs and fees3bps/slippage2bps per side produce24 context/cost runs, not24 distinct strategies. All source signal/fill/mark events, daily equity, closed-return statistics, costs, drawdown, Sharpe and expectancy matched the frozen source/account references within the recorded field-specific binary64 comparison contract. Actual production detail/readiness/selected-summary/optimizer JSON also matched across24 cases, including serialized per-trade returns, fee/slippage return deductions, points, calendar holding days and null unsupported monetary/exact-excursion fields:66,312 serialized daily equity points and10,996 independent rule-state values. Malformed/unknown settings, unsupported costs/sizing/coverage and forged stock identity requests are tested separately. Six-decimal API formatting is checked against its explicit rounding bound; rule predicates/dates are never repaired with tolerances.

These are selected-stock price-data research checks. They do not certify global quote adjustments, complete exchange calendars, historical constituents, short availability, original study performance or full book conversion. Source files and actual outputs remain private and outside Git. A calendar cross-check found a supplied SPX row on2001-09-11 despite the US equity-market closure confirmed by [NYSE history](https://www.nyse.com/history-of-nyse) and the [SEC recovery record](https://www.sec.gov/investor/mktrecovery.shtml). That index is not treated as a certified exchange calendar, and no stock bars are fabricated to match it. The checked Indian stock/calendar intervals agree; that is a scoped comparison, not an exchange-calendar census.

The compiled release was also checked through actual HTTP transport:24 selected-stock cases across detail, summary, readiness and fixed-setting optimization. Optimizer elapsed milliseconds are intentionally variable. The loaded India runtime supplies auxiliary VIX diagnostic values that were absent in the isolated function fixtures; those values are not Kestner rule inputs and their numeric accuracy is not independently certified by this batch. All other compared response content matched. Unsupported instrument/settings/coverage requests and basket holds were checked separately.

After the engine-only deployment, fresh authenticated LAN requests matched72 Kestner responses, eight existing DEMA/Pristine run controls and regional catalogue definitions to the checked runtime. Real-browser checks confirmed all three methods on AAPL and RELIANCE, correct closed-trade counts, desktop/mobile layouts and disabled unreviewed basket execution. Account roles and saved preferences were preserved. Fresh availability evidence was deduplicated by book and method; multiple instruments or cost runs do not become additional strategies. Staged evidence retains its actual provenance and is bound to the identical deployed image and executable, rather than being relabelled as live capture. The two-sheet inventory workbook is derived separately from that approved evidence.
