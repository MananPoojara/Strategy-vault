# Bounded QTS visual rule evidence

The visual guide has dedicated calculated inputs for five reviewed individual-stock methods: `hbqts_stoch_rsi`, `hbqts_ma5_25`, `hbqts_ma1_36`, `hbqts_fixed_interval`, and `hbqts_entry_id1`. The provider reads an existing run and full actual stock history. Opening it does not run, optimize, admit or change a strategy. Other Bandy methods continue through the existing visual-guide path.

The source basis remains [the reviewed companion translation](REVIEW-2026-10-13.md), the active constants and assignment order in Figures 10.3, 7.1, 13.2, 7.6 and 7.14, and the existing `hbqts/reviewed.rs` implementation. This work adds presentation evidence; it does not alter Rust strategy calculations. Exact visual evidence means the declared engine formula arithmetic is traced. It does not certify native AmiBroker exports, source database history, original book accounting, historical universe membership, or book-reported performance.

| Method | Calculated inputs and conditions |
| --- | --- |
| Stochastic RSI | Published P=N=0 RSIa recurrence from source bar 1, first ratio at its period; full finite-window RSI HHV/LLV; range fraction; first-finite DEMA trigger; adjacent strict upward/reverse Cross. A flat RSI denominator or zero range stays missing. Missing smoothing output stays missing while its prior finite recursion state survives; Cross does not bridge a gap. |
| MA 5/25 and active MA 1/36 examples | Fresh-window oldest-to-newest SMA sums and the two strict crosses. Today's `fast > slow` requires yesterday's `fast <= slow`; reverse Cross supplies Sell. An equal pair alone does not cross. |
| Fixed interval | Absolute loaded source `BarIndex % every == 0`, BarsSince of raw Buy, and Sell-only ExRem. The first actual loaded quote is index zero. A raw repeated Buy resets the clock even while held. |
| Entry identification 1 | Raw MA Buy Cross, BarsSince of raw Buy, raw holding threshold, then sequential Buy ExRem and Sell ExRem. Repeated raw crosses can reset the clock without producing another cleaned Buy or fill. No opposite-MA exit or ApplyStop is added. |

The guide uses resolved selected parameters, never guessed defaults. Full source history supplies seeds, bar origin and formula state before the selected From date. The source examples' literal defaults and selected parameter variants remain distinct. The effective integer conversion follows the existing engine's rounded, minimum-one periods, within the visual helper's 10,000-bar bound.

Only a ready run bound to full, ordered, source-qualified `individual_stock` OHLC receives this trace. The native qualified ticker, symbol and source/CSV hash fields must be present and match the selected constituent or single-stock ledger. The central model also binds the selected run's source identity to the price history. Index, ETF and unqualified cached arrays do not substitute for stock prices. Unknown book identity, sliced history and unresolved parameters leave the trace unavailable. Neither hashes nor a catalogue listing establish historical population membership.

Raw formula predicates, cleaned formula arrays, source position permission and accepted fills are separate inspector rows. Source position checks require the existing validated single-stock close-entry ledger: long/cash, one full entry leg, no overlap and no pyramiding. Each recorded entry and exit must exist in the actual price history as well as the selected run dates. A closed close-only position cannot enter and exit on the same candle; a terminal open entry and mark may share a date. Same-close entries are not holdings before that close; a completed exit belongs to its actual exit day. A terminal open mark never creates an exit fill. The single-stock account starts flat at the selected From date while formula arrays retain their complete earlier state. Same-bar Close execution is the existing declared research convention; Figure 13.2 omits delays/prices and uses that reviewed selection.

In a basket constituent view, the ledger establishes accepted exposure only. Accepted holdings can prevent an additional source entry, but accepted flat exposure cannot prove that the underlying source runner was flat: a capacity-rejected source position can still govern its next eligible event. The unprovided source/controller permission remains unknown. Arrows and recorded-fill checks always come from accepted positions; raw conditions do not manufacture arrows.

Verification uses focused arithmetic and state fixtures, prefix causality, missing-data and instrument guards, and fresh actual AAPL/RELIANCE runs for the five methods. Full-history raw Buy, cleaned Buy and Sell flags are compared to the unchanged reviewed Rust signal-array harness; selected-day position permission and fill rows are compared to actual accepted API ledgers. This checks frontend correspondence to the declared engine reconstruction. It does not upgrade the earlier source review or prove original native-platform parity. Private market data, complete API bodies, numerical receipts and browser screenshots remain outside Git.

Integration calls `buildBandyRuleEvidence(model, prices)` after the central full-history guard. The central model supplies `book`, `ledgerAvailable`, and basket-only `focusTicker`; unknown method IDs return `null`. Missing position state with valid formula inputs preserves calculated indicator evidence while withholding permission/fill assertions. The provider changes no account, admission, worker, data or execution behavior.
